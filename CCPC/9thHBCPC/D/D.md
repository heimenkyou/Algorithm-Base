### 一、 大白话翻译题面

**1. 初始状态：**
你手头有一个包含 $n$ 个正整数的数组（代表 $n$ 种饺子的美味度）。
*数据范围：数组长度 $n$ 最大到 $10^6$，里面的数字最大到 $10^8$。*

**2. 操作规则：**
你需要在数组里任选两个**位置不同**的数字配对，这一对数字的“代价”是它们差值的绝对值（大数减小数）。
全场最多能配出 $\frac{n(n-1)}{2}$ 种不同的对子。

**3. 终极目标：**
你需要从所有可能的配对中，挑出整整 **$k$ 对**。
要求这 $k$ 对的**代价总和最小**。最后输出这个最小的总和。
*极端数据范围：$k$ 的最大值高达 $10^{11}$！*

---

### 二、 从破防到破局的思路推导

在赛场上，面对这道题，正常的思维一般会经历以下三个阶段。我们一步步来看怎么识破它的伪装。

#### 第一层直觉：排序 + 贪心找相邻（必然会错的诱惑）

既然要差值最小，那选出来的两个数字肯定大小要接近。第一步**必须对数组从小到大排序**。
排完序后，很多人（包括赛场上的很多队伍）第一反应是：我直接选相邻的数字配对不就好了？

* **为什么错？** 因为 $k$ 可能非常大！比如数组是 `[1, 2, 3, 100, 101]`。相邻对子的差值有 `1 (2-1)`，`1 (3-2)`，`1 (101-100)`。如果你需要选 4 对，除了这 3 对相邻的，你还得挑跨越一个数字的对子，比如 `2 (3-1)`。所以，答案绝对不仅仅是相邻对子。

#### 第二层直觉：优先队列/堆排序（TLE 与 MLE 的深渊）

既然不只是相邻对子，那用个小根堆（优先队列）行不行？
先把所有相邻对子的差值塞进堆里，每次弹出一个最小的。弹出一个 $(i, i+1)$ 时，再把跨两步的 $(i, i+2)$ 塞进堆里……这样弹 $k$ 次，把弹出的差值累加起来。

* **为什么被毙掉？** 看看数据范围！$k$ 最大是 **$10^{11}$**！
把 $10^{11}$ 个元素塞进堆里再弹出来，你的程序估计要跑十分钟，而且内存会直接爆表（题目给的 1024MB 内存连 $10^8$ 个对象都存不下）。
**记住一个铁律：在算法竞赛中，当需要求“前 $K$ 个最值”，且 $K$ 的数量级大到离谱（超过 $10^7$）时，优先队列和传统排序必死无疑。**

#### 第三层境界：二分答案 + 双指针（真正的屠龙技）

既然从正面（挨个挑对子）走不通，我们必须**逆向思维**。

差值最小是 $0$，最大是 $10^8$。与其去数前 $k$ 个对子是谁，不如我们直接在 $[0, 10^8]$ 这个范围内去猜（二分）第 $k$ 大的差值是多少。

我们假设一个差值阈值 `mid`，然后去问计算机一个问题：

> “在排好序的数组里，差值**小于等于** `mid` 的对子，一共有多少个？”

1. **怎么高效数数？（双指针）**
因为数组已经排好序，我们可以用两个指针 $L$ 和 $R$。
$R$ 从左往右扫，对于每一个 $R$，$L$ 一直往右挪，直到 $a[R] - a[L] \le mid$ 为止。
那么在这个 $R$ 结尾，差值符合条件的对子就有 $R - L$ 个。
这个过程只需要遍历一遍数组，时间复杂度是极其优秀的 $O(n)$。
2. **怎么二分逼近？**
* 如果数出来的个数 $< k$，说明我们猜的阈值 `mid` 太严了，放宽一点，让 `left = mid + 1`。
* 如果数出来的个数 $\ge k$，说明阈值够了，甚至可能偏宽松，我们尝试收紧，让 `right = mid - 1`，同时记录下当前的 `mid`。
最后，二分结束时，我们就精准地找到了那个**分界线差值 $D$**（即第 $k$ 小的差值）。


#### 最后的拼图：如何快速求和？

找到这个差值界限 $D$ 后，我们知道最终答案主要由所有差值**严格小于** $D$ 的对子贡献。
但这可能有几千万甚至几十亿对，难道又要用**双指针**（双指针原始解法见[下方详解](#补充-原始双指针解法) ）一个一个减了加起来吗？当然不行！还是会超时。

既然我们要算 $\sum_{j=L}^{R-1} (a[R] - a[j])$，把它拆开就是：
$(R - L) \times a[R] - (a[L] + a[L+1] + \dots + a[R-1])$
发现没有？后面那一串就是一个**区间和**！
这就呼出了算法竞赛里另一个极为常用的基础工具：**前缀和**。我们提前花 $O(n)$ 的时间预处理一个前缀和数组，这一长串加法就可以在 $O(1)$ 的时间用 $S[R-1] - S[L-1]$ 算出来。

**收尾防坑：**
所有差值 `< D` 的对子算完和之后，总个数可能比如是 $cnt$ 个，还没达到 $k$ 个。剩下缺少的 $(k - cnt)$ 个对子，它们的差值一定**刚好等于 $D$**。把这部分补上，就是最终答案。

---

**总结一下这道题的破局链条：**
因为求前 $K$ 小元素且 $K$ 极大 $\rightarrow$ 放弃优先队列 $\rightarrow$ 采用**二分答案**猜差值界限 $\rightarrow$ 利用有序数组的性质配合**双指针**高效验证 $\rightarrow$ 利用**前缀和** $O(1)$ 批量求和降维打击。

## 补充-原始双指针解法

假设我们现在通过二分答案，已经定下了一个差值门槛 $D = 5$。
现在的核心任务非常明确：**在一个已经从小到大排好序的数组里，找出所有“差值 $\le 5$”的对子到底有多少个。**

---

### 第一层：普通人的暴力思路（一定会超时）

如果要找差值 $\le 5$ 的对子，最直白的写法就是两层循环：拿右边的数减去左边的数，看看超没超标。

```python
cnt = 0
for R in range(n):
    for L in range(R):
        if a[R] - a[L] <= 5:
            cnt += 1  # 找到了一个

```

这个写法的致命问题是：如果数组有 10 万个数字，你要循环 100 亿次，绝对会超时。我们需要利用“数组已经从小到大排好序”这个极其重要的物理性质。

---

### 第二层：高手的双指针（Two Pointers）魔法

想象一根带刻度的尺子，上面标记了数组里的所有数字。我们用两根手指头来指数字：

* **右手指 $R$（主动出击）**：从左往右一步步走。它代表“我现在固定把 $a[R]$ 当作这一对里面的大数”。
* **左手指 $L$（被动追赶）**：它代表“能跟 $a[R]$ 配对的、最靠左的小数”。

**核心运行规则：**

1. $R$ 往右走了一步。
2. 此时拉开了距离。我们看看 $a[R] - a[L]$ 的差值是不是大于了 $5$。
3. 如果大于 $5$（说明 $L$ 指向的数太小了），$L$ 必须赶紧往右移动（因为越往右数字越大），直到差值重新缩小到 $\le 5$ 为止。
4. 一旦差值达标，说明从 $L$ 开始，一直到 $R-1$ 的所有数字，跟 $a[R]$ 的差值都 $\le 5$。这一波直接找到了 `R - L` 个合法的对子！

---

### 举个具体栗子模拟一下

假设数组是：`[1, 2, 8, 9, 10]`，门槛 $D = 5$。
一开始 $L = 0, R = 0$。

* **回合 1：** $R$ 走到数字 `2` (下标 $1$)。
* 检查：$2 - 1 = 1 \le 5$。合法。
* 找到了几个对子？$R - L = 1 - 0 = 1$ 个。也就是 `(1, 2)`。


* **回合 2：** $R$ 走到数字 `8` (下标 $2$)。
* 检查：$8 - 1 = 7 > 5$。**超标了！**
* 于是 $L$ 必须往右追。$L$ 走到数字 `2`。
* 再次检查：$8 - 2 = 6 > 5$。**还是超标！**
* $L$ 只能继续追。$L$ 走到数字 `8`。
* 检查：$8 - 8 = 0 \le 5$。终于合法了。
* 找到了几个对子？$R - L = 2 - 2 = 0$ 个。说明此时没有任何前面的小数能跟 `8` 配对。


* **回合 3：** $R$ 走到数字 `9` (下标 $3$)。
* 此时 $L$ 还在指向数字 `8`。
* 检查：$9 - 8 = 1 \le 5$。合法。
* 找到了几个对子？$R - L = 3 - 2 = 1$ 个。也就是 `(8, 9)`。


* **回合 4：** $R$ 走到数字 `10` (下标 $4$)。
* 此时 $L$ 还在指向数字 `8`。
* 检查：$10 - 8 = 2 \le 5$。合法。
* 找到了几个对子？$R - L = 4 - 2 = 2$ 个。也就是 `(8, 10)` 和 `(9, 10)`。



---

### 把文字变成极其简练的代码

这段模拟过程，写成 Python 代码只有寥寥几行，这就是**双指针的标准模板**：

```python
cnt = 0  # 记录合法对子的数量
L = 0    # 左指针初始在最左边

for R in range(n):  # 右指针 R 每次主动往右走一步
    
    # 当差值超标时，左指针 L 就不断向右追赶
    while a[R] - a[L] > D:
        L += 1
        
    # 当 while 循环结束时，说明 a[R] - a[L] <= D 已经达标了
    # 此时 L 到 R-1 之间的所有数字，都能和 a[R] 组成合法对子
    # 一波直接加上 R - L 个！
    cnt += R - L

```

**为什么它快？**
你看代码虽然是 `for` 循环里套了个 `while` 循环，但你仔细看 $L$ 指针：**它永远只会往右走，从来不会回头！**
哪怕 $R$ 走了 10 万步，$L$ 最多也只是跟着走了 10 万步。所以电脑的总操作次数是 $O(N)$ 级别，几毫秒就能跑完，这就叫双指针的降维打击。

这下再回过头看，我们前面说的那一堆“复杂的前缀和求和公式”，其实就是塞在了 `cnt += R - L` 这句话的下面，在我们数出对子个数的同时，顺手把这些对子的差值用 $O(1)$ 的公式给加起来而已。
